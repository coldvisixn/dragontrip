# Dragontrip: цель → исследование → проверка

Работа в текущем checkout, исходный коммит `1a5e60d`. На момент начала изменений рабочее дерево было чистым; `docs/experience/README.ru.md` отсутствовал. Этот документ описывает реализованное изменение, воспроизводимые проверки и оставшиеся ограничения. Отчёт относится к реализации 0.10.0; [проверка выпуска и установщика](../BUILD-0.10.0.md) ведётся отдельно от локальных измерений.

## Аудит и приоритеты

Наблюдения получены из запущенного приложения с реальным backend, из воспроизводимых сценариев и проверки сохранённых данных. Оценки понятности ниже — экспертные гипотезы, а не результаты исследования с пользователями.

| Приоритет | Подтверждённая проблема и пример | Изменение |
|---|---|---|
| P0 | Повторный POST запуска создавал отдельное задание; потерянный ответ нельзя было безопасно повторить | Сохраняемый receipt `request_id`, проверка содержимого и сериализация запуска |
| P0 | Остановка/ошибка удаляла файл вывода; промежуточные результаты пропадали | Ограниченный по размеру исходный файл сохраняется; закрытые записи Nmap/httpx проецируются как частичные |
| P0 | Получение завершённого задания могло опередить обновление объектов в UI; переход к web-результату открывал пустое представление | Перед переходом загрузить актуальный detail; выбирать объект из этого ответа |
| P1 | Несколько React-компонентов Inspector/knowledge имели одинаковые ключи; повторное обновление размножало редактор объекта | Разные ключи для редактора, связанных записей и наблюдений; регрессионный тест |
| P1 | Scope находился в Recon, overview/методологии — в дополнительных страницах Research; проект не имел отдельной цели | Раздел Plan, поле цели с миграцией, предлагаемый следующий шаг из backend |
| P1 | Боковая навигация конкурировала с верхними вкладками и More; горизонтальная полоса отнимала высоту | Одна вертикальная навигация внутри sidebar, все страницы активного раздела видимы |
| P1 | Панель заданий смешивала результат и технический вывод; пользователь должен был искать результат в графе | Компактная строка фоновой работы, раскрываемые результат/ошибка/действия и отдельно технический вывод |
| P1 | Закрытие Inspector сбрасывало выбранный объект | Видимость Inspector отделена от выбора и сохраняется для проекта |
| P1 | Известный HTTP-сервис требовал ручного переноса адреса в веб-исследование | Идемпотентный локальный переход service → application; сетевой запрос — отдельный план с разрешением |
| P1 | После импорта не было прямых переходов к соответствующим объектам | Действия открытия web/infrastructure/findings в сохранённом результате импорта |
| P2 | Список endpoint и детали располагались последовательно, затрудняя сопоставление | Две рабочие колонки, ограниченная прокрутка деталей, выбор сохраняется |

Проверить с реальными пользователями: понятность четырёх разделов проекта; выбор терминов Plan/Research/Recon/Notebook; достаточно ли одной предлагаемой следующей операции; удобство компактного sidebar и раскрываемого результата. Время выполнения задач пользователями и снижение ошибок не измерялись.

Глобальные действия находятся в sidebar. Страницы относятся к активному проекту. Заголовок показывает местоположение и цель; действия экрана расположены в рабочей области. Действия объекта находятся в Inspector или деталях endpoint. Фоновое выполнение не блокирует остальную работу. Закрытая служебная панель не отнимает место у графа. История Back/Forward, поиск Ctrl+K, выбор, фильтры, viewport графа и существующие черновики сохранены.

На одинаковом fixture высота основной области при открытом Inspector увеличилась на 47 px за счёт удаления горизонтальной навигации. При 1000×650 Inspector занимает 300 px и оставляет графу 515 px (до — 550 px); его можно скрыть, сохранив выбор. Это компромисс в пользу читаемых действий объекта, не универсальное увеличение площади. Горизонтальный скролл документа на проверенных экранах отсутствует.

## Реализованный сквозной путь

Создать проект и цель → задать scope → посмотреть план → разрешить Nmap → открыть сохранённый сервис → локально перейти в web → отдельно разрешить HTTP-запрос → импортировать Burp → посмотреть ответ, наблюдение и исходный файл → создать гипотезу → связанную задачу и её результат → находку → ручной ретест → перезапустить frontend/backend → экспортировать и импортировать проект с проверкой сохранённых сущностей.

В демонстрации сетевые действия направлены исключительно на собственный `127.0.0.1:8080`; Burp-данные — статический fixture. Гипотеза и находка синтетические. Ретест — запись ручной проверки, не автоматическое доказательство уязвимости.

## Профили производительности

В исходной копии отсутствовали именованные Low / Medium / High: были auto/full/compact и reduced motion. Добавлены явные профили. Medium сохраняет прежние пороги; Low отключает minimap и фон графа, упрощает линии и движение, раньше уплотняет карточки; High дольше сохраняет полные карточки. Ручной выбор детализации и лимит minimap до 500 объектов сохраняются во всех профилях. Это настройка отображения, не интенсивности сканирования.

## Границы выполненного

Реализованы компоновка, путь от цели до результатов и связанного исследования, защищённый запуск сканирования, частичные результаты, контекст и перенос проекта. Существующие специализированные модули methodology/workflow, Vault, report и draft сохранены и проверяются своими тестами. Универсальный workflow engine не вводился.

Остаются: тесты с реальными пользователями; нативная матрица на целевой Kali с установленным release-пакетом; автоматическое сравнение произвольных HTTP-тел/скриншотов между ретестами; возобновление внутри процесса внешнего инструмента. Числовой процент завершения внешнего инструмента не придуман: показываются очередь, выполнение, сохранение и терминальное состояние. Существующие лимиты live-адаптеров (IPv4, не диапазоны/hostname/IPv6), импорта, архивов и доказательств сохраняются.
