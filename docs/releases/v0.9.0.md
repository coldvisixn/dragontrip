## Dragontrip 0.9.0 — Pick up your investigation where you left it

A local desktop workspace for HTB and similar authorized labs: open a target, collect observations, keep hypotheses and unsuccessful checks, and resume after restarting.

### What's new

- **Keep your work:** project-specific navigation, graph view, web application/endpoint selection, searches, filters and open editors recover across restart. Research drafts sync to SQLite with an immediate browser recovery copy. Conflicts show both versions and timestamps, with separate-copy, saved-version and manual-merge actions. Replaced text remains recoverable. Native close warns about memory-only research text and can export recovery JSON.
- **Work from evidence:** create draft findings, notes or tasks directly from observations, imports, scans, services and endpoints. Known objects, source identifiers, runs and evidence are linked automatically, with navigation back to the source. Existing linked records appear before creation; repeated clicks and reimports reuse the record.
- **Keep the next check nearby:** turn hypotheses into tasks, link notes and checks, retain unsuccessful results, and use small editable investigation templates. Findings remain drafts until you decide otherwise.
- **Run approved sequences:** preview all selected targets, tools and parameters, then run a saved recon sequence. See its current step, results and stop reason; pause, cancel or retry while retaining attempt history. Restart and project import pause automatic execution. Scope and adapter restrictions still apply at each step.
- **Less interface overhead:** Research, Recon and Notebook group the main workflow, secondary pages stay in contextual menus, optional metadata is collapsed, and the terminal appears when needed. Running tool status stays accessible.

Existing manual retests, evidence, vault, methodologies and reviewed Markdown/HTML/ZIP reports remain available. No customer fields or mandatory finding-completeness gates were introduced.

### Install or upgrade

Download **`dragontrip_0.9.0_amd64.deb`** and **`dragontrip_0.9.0_amd64.deb.sha256`** from this release's **Assets**.

```bash
sha256sum --check dragontrip_0.9.0_amd64.deb.sha256
sudo apt update
sudo apt install ./dragontrip_0.9.0_amd64.deb
dragontrip
```

Linux x86_64 (`amd64`). Python, Node.js, Rust and Docker are not runtime requirements. Recon tools are optional: `sudo apt install nmap whatweb httpx-toolkit ffuf` on Kali; httpx must be the ProjectDiscovery implementation.

**Close Dragontrip and back up the complete data directory before upgrading.** 0.8.0 research drafts migrate without deleting their originals. Project archives now use **v5**, retaining source links, workspace recovery and append-only retests; v1–v4 imports remain supported. Older apps reject v5. Do not open upgraded data with an older application.

### Limits

This remains a **0.x MVP / Pre-release**. Research drafts and retained recovery text are unencrypted and are included in v5 project transfers; review before sharing. Reports exclude drafts and vault data; report compositions remain local. Text that exists only in memory cannot survive forced process termination or OS failure. UI is English; Windows/macOS/ARM installers are not supplied. Live adapters retain their existing individual IPv4 target/origin limits. Recommendations explain their source observations and do not validate vulnerabilities or start exploitation.

The release workflow builds its own Ubuntu 24.04 package, tests the frozen backend and installed Tauri/WebKit scenarios, and publishes the installer with its matching checksum only after success. Local test details and platform limits: [build evidence](https://github.com/coldvisixn/dragontrip/blob/v0.9.0/docs/BUILD-0.9.0.md), [research and recovery](https://github.com/coldvisixn/dragontrip/blob/v0.9.0/docs/HTB-WORKSPACE.md). Hardware acceptance on your particular Kali/VirtualBox setup and feedback from other users remain separate from automated checks.
